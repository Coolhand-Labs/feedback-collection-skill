description: Automated review → fix → repeat loop for this skills repo. Runs the repo's deterministic checks (build-skills, validate-patterns, check-trusted-urls) plus a reviewer agent each round, fixes findings, and repeats until both come back clean.
allowed-tools: Edit, Write, Read, Bash, Agent, Skill, Glob, Grep
argument-hint: [low|medium|high|max]

Run an automated review + fix loop on the current branch. Keep iterating until the repo's deterministic checks pass AND the reviewer agent reports no issues.

## Setup

- Effort level: `$ARGUMENTS` (default: `high` if blank)
- Max iterations: 5
- Review scope: `git diff origin/main...HEAD`

This repo is a Claude Code plugin made of generated skill prompts (`SKILL.md`, built from `SKILL.src.md` + `skills/shared/common.md`), lookup YAML (`detection-patterns/providers.yml`, `source_apis.yml`), a handful of Ruby/Bash/Python maintenance scripts (`bin/*`), and a URL trust policy (`.trusted-urls.yml`). Unlike a normal application repo, most "bugs" here are prompt-engineering or convention violations, not runtime logic errors — the loop below is built around that.

## Loop Instructions

Repeat the following cycle up to 5 times:

### Step 1 — Deterministic checks (Bash)

Run, in this order, and capture full output:

```bash
bin/build-skills --self-test
bin/build-skills --check
bin/validate-patterns --self-test
bin/validate-patterns
bin/check-trusted-urls --self-test
bin/check-trusted-urls
```

These are exact, not judgment calls — treat every failing line as a finding, same as a reviewer-reported issue. (Skip `bin/check-skill-urls` inside the loop; it does live network GETs per URL and is too slow/flaky to gate iterations on. Mention it in the Final Summary as a suggested one-time check before merging if any `SKILL.md` or `references/*.md` changed.)

### Step 2 — Review (Agent)

Spawn an Agent using the Agent tool with `thinking: "high"` enabled and this prompt (substitute ITERATION_NUM, EFFORT, and PREVIOUS_FIXES):

---
You are a code reviewer doing pass ITERATION_NUM of an automated review loop on the `feedback-collection-skill` plugin repo.

Run `git diff origin/main...HEAD` to get the current branch diff, and read `CLAUDE.md` for this repo's conventions before judging anything. Review the diff for:

- **Hand-edited generated files.** `skills/*/SKILL.md` is generated by `bin/build-skills` from `SKILL.src.md` + `common.md` — it must never be edited directly. If a `SKILL.md` changed without a matching change to its `SKILL.src.md` (or the diff doesn't look like exactly what `bin/build-skills` would produce), flag it.
- **Frontmatter conventions.** `description` in `SKILL.src.md` must contain triggering conditions only (symptoms, slash-command aliases, package names) — not a workflow/phase summary (see CLAUDE.md "SKILL.md description field"). `shared_common: true` should be present only on `SKILL.src.md` files that actually reference `source_apis.yml` / `detection-patterns/providers.yml`; flag it on skills that don't need that prose, or missing on ones that do.
- **Inline content that belongs in YAML.** Per-provider or per-language snippets (SDK import patterns, extraction code, host names) added directly into a `SKILL.src.md` instead of `detection-patterns/providers.yml` or `source_apis.yml` (see CLAUDE.md "No language-specific instructions inline in SKILL.md").
- **Versioning/CHANGELOG discipline.** Any `SKILL.src.md` content change should bump that skill's `version` field and get a `CHANGELOG.md` entry under `## Unreleased`; a content change with neither is a finding. Conversely, a version bump with no `CHANGELOG.md` entry (or vice versa) is a finding.
- **Cross-file consistency.** Relative path references between skills (`../feedback-collection/...`, `../self-hosted-feedback/references/...`), phase names/numbers referenced from a sibling skill, and `README.md` — do these still resolve and match after the change?
- **Trusted URL policy.** Any new `http://`/`https://` reference not covered by an existing prefix in `.trusted-urls.yml`.
- **"Rationalizations to resist" tables.** Entries should not be softened or removed without cause; new entries should read like they came from an observed session, not a hypothetical.
- **Correctness, security, and reuse issues** in any touched `bin/*` script (Ruby/Bash/Python) or the YAML schema files, same as a normal code review.
- **PR scope.** Note (don't block on) whether the diff bundles unrelated concerns that CLAUDE.md's "Commits and PRs" section says should be separate PRs.

Effort: EFFORT

Already fixed in prior iterations — do NOT re-flag these:
PREVIOUS_FIXES

Return a numbered list of issues with file path and line numbers. Be specific about what to fix and why.
If there are NO issues (and the deterministic checks passed), respond with exactly: LGTM: No issues found.
---

### Step 3 — Check Result

- If the deterministic checks passed AND the agent says `LGTM: No issues found.` → exit the loop, go to Final Summary
- If iteration count has reached 5 → exit the loop, go to Final Summary (partial)
- Otherwise → proceed to Step 4

### Step 4 — Fix

Fix every issue from both the deterministic checks and the reviewer. For a stale/hand-edited `SKILL.md`, the fix is to correct `SKILL.src.md` (or `common.md`) and re-run `bin/build-skills` to regenerate it — never hand-patch the generated file. Use Edit, Write, and Bash tools to apply the rest directly. Do not skip any finding.

### Step 5 — Log & Continue

Record this iteration in your running log (see format below), then go back to Step 1 with the next iteration number.

## Iteration Log Format

Maintain this log as you work:

```
=== Iteration 1 ===
Deterministic checks: [PASS | FAIL — list of failing checks]
Reviewer found N issues:
  1. [file:line] description
  2. ...
Fixed:
  - Applied: [description of fix]
  - Applied: [description of fix]

=== Iteration 2 ===
...

=== RESULT ===
[CLEAN after N iterations] or [STOPPED at max iterations — N issues remain]
```

## Final Summary

After the loop exits, output:

1. **Overall result**: CLEAN (N iterations) or STOPPED (issues remain)
2. **Per-iteration breakdown**: What was found (deterministic + reviewer) vs. what was fixed each round
3. **All files modified**: Complete list of files touched across all iterations
4. **Remaining issues** (if stopped at max): Unresolved items with context on why they're hard to fix automatically
5. **Suggested follow-up**: If any `SKILL.md` or `references/*.md` changed, recommend running `bin/check-skill-urls` once before merging (not run automatically by this loop)
