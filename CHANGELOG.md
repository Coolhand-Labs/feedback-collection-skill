# Changelog

## Unreleased

- **Guardrail: no synthesis when get-optimization fails (issue #15):** Phase F.2 now has an explicit error-handling rule — if `coolhand get-optimization` returns an error, report it and stop; do not reconstruct `analysis`, `plan`, or `orchestrator_messages` from search results. Added the corresponding rationalization to the "Rationalizations to resist" table (observed in a live session where a parameter name bug caused all calls to fail and Claude fabricated a complete summary). Bumped `coolhand-integration` to 0.3.2.
- **Planner ↔ wildcard-tool wiring.** The `feedback-collection` planner now detects whether each inference-call site does tool-calling (`tool_calling_detected`, Phase 1), surfaces a conditional WILDCARD OPPORTUNITY block in the Phase 4 proposal, and offers a one-time wildcard follow-up after dispatch (Phase 5). The Phase 1 detection guidance is kept high-level (MCP server / explicit tool-call loop / tool instructions in the prompt) rather than a grep checklist, and the Phase 5 offer is framed as "set up the wildcard tool for your agents." Bumps `feedback-collection/SKILL.md` to 0.2.0.
- **wildcard-tool framing, kill threshold, and monitoring guidance.** Adds a "Framing the tool" section (present it as a capability-request tool, not a complaint channel) that also acknowledges the current implementation still collects a free-form `complaint` field. Adds a success-flavored-return-string anti-pattern and a kill-threshold recommendation to the Tool contract, with a caveat not to build run-capping infrastructure that the project doesn't already have — ask the developer or note it for later. Rewrites monitoring guidance toward end-of-day review in active development and weekly batch review in production, explicitly against real-time per-call alerting. Bumps `wildcard-tool/SKILL.md` to 0.4.0.

## v0.3.2 — 2026-06-04

- **Rewrote `wildcard-tool` skill as a consultant, not an installer.** Removes the stack-detection installer, the three language templates (Python, TypeScript, Ruby), and the assumption that CLAUDE.md is the agent's instruction surface. The skill now advises the developer's AI on three things: where the agents in this project live and read their instructions (Phase 0 investigation), what surface to expose the wildcard tool through (Phase 2 exposure, balanced across KISS, agent visibility, and per-call token cost), and how to wire the tool's payload (through an installed Coolhand SDK if present, otherwise a minimum wire format the developer's AI implements). Drops the four-field input schema in favor of one free-form `complaint` from the agent plus a framework-captured `original_output` (last 20 lines of the thinking chain) and a `creator_unique_id` set at registration to the agent's actual name. Bumps `wildcard-tool/SKILL.md` to 0.3.0.

- **coolhand-cli v0.3.1 compatibility:** update F.3 version gate and all version fields to v0.3.1+.

- **coolhand-cli v0.3.0 compatibility:** drop the filter-type parenthetical from the `search-optimizations` one-liner in F.2 — it was already incomplete after CLI additions (pagination, sort, workload/template filters) and will keep drifting; `coolhand help search-optimizations` is the authoritative flag reference. Update F.3 version gate from v0.2.0+ to v0.3.0+: v0.2.0's `get-optimization` had a broken MCP parameter (`id` instead of `optimization_id`) making all calls fail; v0.3.0 is the first fully correct release.

- **Private key and MCP optimization tools (issue #10):** `coolhand-integration` gains a new Phase F covering private key acquisition via `coolhand login --scope private --write-env .env` (CLI writes both `COOLHAND_API_KEY` and `COOLHAND_PRIVATE_KEY`), six new CLI subcommands for optimization operations (`search-optimizations`, `get-optimization`, `add-optimization-comment`, `close-optimization`, `create-optimization`, `update-optimization`), and a CLI-upgrade fallback (F.3) for users on older CLI versions. Former Phase F (post-implementation checklist) becomes Phase G. Requires coolhand-cli PR #4 (issue #3). Bumped `plugin.json`, `marketplace.json`, and `coolhand-integration/SKILL.md` to 0.3.0.
- **Browser-based token acquisition (issue #6):** when no API key is found, the skill now offers a browser auth flow before falling back to the manual copy-paste path. For managed Coolhand, the skill runs `coolhand login --write-env <path>` (`npx coolhand-cli login` for a zero-install one-shot); for self-hosted, users generate an opaque secret. The skill asks where to write the key rather than assuming `.env`, and the gate now accepts either `COOLHAND_API_KEY` (managed) or `FEEDBACK_API_KEY` (self-hosted).
- **CLI-first convention in CLAUDE.md:** added a section codifying the pattern — prefer `coolhand <subcommand>` over inline implementation; if no CLI command exists for the needed operation, ask whether to file a tracking issue on coolhand-cli before adding inline detail.

## v0.1.0 — 2026-05-08

- Relicensed from MIT to Apache-2.0.
- Rewrote SKILL.md `description` frontmatter to triggering conditions only. The previous description summarized the workflow, which (per Anthropic / superpowers eval evidence) causes Claude to act on the summary rather than read the body and follow its phases.
- Added a Claude Code plugin manifest (`.claude-plugin/plugin.json`) and a single-plugin marketplace manifest (`.claude-plugin/marketplace.json`) so the skill installs via `/plugin marketplace add` instead of manual `cp -r`. Updated the README install section to match. Removed the previous `~/.claude/skills/coolhand` instructions, which silently failed (the source dir is `skills/feedback-collection/`, not `skills/coolhand/`).
- Added a "Rationalizations to resist" section to SKILL.md codifying the three guardrails most likely to be bypassed under pressure: hashing the `creator_unique_id` (no PII), per-UI-change approval (every widget needs its own diff + sign-off), and the `COOLHAND_API_KEY` prerequisite (stop and wait, do not "wire it up and let the user fill it in later").
- Externalized Phase 1 detection patterns to `skills/feedback-collection/detection-patterns/providers.yml`. Adding a new LLM provider is now a YAML edit, not a SKILL.md edit. Added `bin/validate-patterns` (Ruby stdlib only — no Bundler, no Gemfile) and a GitHub Actions workflow that runs it on every PR touching the patterns or the validator. The validator includes a `--self-test` mode with fixture cases proving it catches each rejection path.
- Added `CLAUDE.md` capturing repo conventions for contributors: detection-patterns YAML schema, when to add a rationalization, version/CHANGELOG rules, and the SKILL.md description-field rule (triggering conditions only).
- Set initial version to 0.1.0 across `plugin.json`, `marketplace.json` plugins entry, and `SKILL.md` frontmatter.
- Rewrote the `marketplace.json` `description` to lead with the audience (AI/LLM product teams) and the three primary capabilities, with a keyword-dense parenthetical (RLHF, evals, preference data) for search and generative-engine discovery.
- Added `bin/check-skill-urls` (Bash + curl) and a `.github/workflows/check-skill-urls.yml` workflow that runs it on PRs touching `SKILL.md` and on a weekly cron. Catches the most likely silent-degradation mode for this skill: Coolhand SDK README URLs in Phase 0 or GitHub issue URLs in Phase 6 rotting under us. Scope is `SKILL.md` only — that is the only file Claude consults at runtime.
- Added a trusted-URL policy: `.trusted-urls.yml` lists every URL prefix permitted anywhere in the repo, split into a `coolhand:` core (Coolhand-owned domains and the `Coolhand-Labs` GitHub org) and an `infrastructure:` tier with justified non-Coolhand exceptions (Apache license boilerplate, Claude Code link, canonical coolhand-js CDN, RFC-reserved test fixtures). `bin/check-trusted-urls` (Ruby stdlib) scans every file and fails on any URL not matching an allowed prefix. Wired into CI on every PR via `.github/workflows/check-trusted-urls.yml`. Removed the `github.com/obra/superpowers/...` citation from `CLAUDE.md` to keep the trust boundary narrow — the verbal reference reads fine without a clickable link.
- **Split the monolithic skill into one plugin with three skills:** `feedback-collection` (planner), `coolhand-integration` (3a — managed Coolhand backend), and `self-hosted-feedback` (3b — user's own backend). The planner does discovery, strategy design, and proposal; at its new Phase 5 it dispatches to one of the two implementation skills based on the user's backend choice. Phase 5's content (SDK install + configure + feedback calls) moved out of the planner and into the implementation skills.
- **Updated planner methodology from the v2 API spike at https://coolhandlabs.com/docs:** teach `sentiment` (string enum: `"like"` / `"dislike"` / `"neutral"`) over the deprecated `like` boolean; enforce a "floor rule" requiring at least one of `client_unique_id` or `original_output` on every feedback submission as a backstop matching field; explicitly instruct the skill not to populate `coolhand_fingerprint_id` (owned by the coolhand-js widget); document `parent_feedback_hashid`, `focus_section`/`focus_range`, and `workload_hashid` as deferred-scope with links to tracking issues.
- Added `skills/self-hosted-feedback/references/coolhand-openapi-v2.json` (snapshot of the v2 OpenAPI spec, extracted from the docs site) and `skills/self-hosted-feedback/references/api-spec.md` (focused implementation reference: endpoints, schemas, auth, SQL schema examples for Postgres/MySQL/SQLite, deferred-field call-outs).
- Filed five companion issues during the split: SDK `base_url` requests on each of the four SDKs (Coolhand-Labs/coolhand-node#33, Coolhand-Labs/coolhand-python#21, Coolhand-Labs/coolhand-ruby#48, Coolhand-Labs/coolhand-js#28) plus four deferred-scope tickets in this repo (#2 mirroring `inference_apis`, #3 parent/partial feedback, #4 `workload_hashid`, #5 v2 API export endpoints for managed→self-hosted migration).
- Tooling caught up with the multi-skill layout: `bin/check-skill-urls` now scans every `skills/**/SKILL.md` and `skills/**/references/*.md` (was a single hard-coded path). Added an `ignore_paths` mechanism to `.trusted-urls.yml` and `bin/check-trusted-urls` for vendored / snapshotted upstream content (used by the OpenAPI spec snapshot, which contains third-party example URLs we don't author). README updated to reflect the three-skill architecture and the `sentiment` / floor-rule changes.
- Added an OpenAPI snapshot freshness mechanism. The snapshot at `skills/self-hosted-feedback/references/coolhand-openapi-v2.json` is now stored in canonical form (`json.dumps(spec, sort_keys=True, indent=2, ensure_ascii=False)` + trailing newline), with a sidecar `coolhand-openapi-v2.meta.json` capturing the snapshot date, SHA-256, and source URL. New `bin/refresh-openapi-snapshot` (Python stdlib, maintainer tool) refreshes the snapshot from coolhandlabs.com/docs and no-ops when the spec hash matches the local meta. 3b's Phase A asks user consent before checking for updates and preserves offline-safe behavior for firewalled environments. Renumbered 3b's subsequent phases (B–I).
- Pre-push hardening: rewrote 3b's Phase A to an agentic freshness check — the skill describes intent (fetch, extract, structurally compare) and lets the agent pick the means (WebFetch, curl, MCP fetcher, anything that retrieves a URL). Removes the runtime Python dependency for end users; `bin/refresh-openapi-snapshot` stays as the maintainer tool.
- Pre-push hardening: tightened `bin/check-trusted-urls` matcher against domain-confusion attacks. URLs that prepend a trusted hostname as a subdomain of an attacker-controlled domain (the `<trusted-host>.<attacker>` pattern) no longer slip through bare-host allowlist entries — the matcher now requires exact match, a trailing-slash prefix, or a path / query / fragment boundary right after the prefix. Allowlist updated with explicit trailing-slash variants where path matches were previously implicit. Self-test extended with a domain-confusion fixture (8/8 passing).
- Pre-push hardening: added abbreviated "Rationalizations to resist" tables to `coolhand-integration` and `self-hosted-feedback` so the three guardrails (no PII in `creator_unique_id`, per-UI-change approval, API key prerequisite) are present at the moment of temptation in the implementation skills, not only in the planner.
- Pre-push polish: Apache-2.0 short header on every script in `bin/`. `bin/refresh-openapi-snapshot` User-Agent now reads the plugin version from `plugin.json`. Added `.gitignore` covering editor noise (`.DS_Store`, `.idea/`, `.vscode/`, `*.swp`), Python/Ruby cache (`__pycache__/`, `*.pyc`, `.bundle/`), and `.env*` for safety.
